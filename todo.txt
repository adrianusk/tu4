Audio: support xu4 `.mod` soundtrack/module files (FUTURE, ~3-5 days)
---------------------------------------------------------------------
Goal: instead of shipping loose `mid/`+`sound/` files in the repo, let tu4
mount an existing xu4 `.mod` (e.g. Ultima-IV.mod, U4-Hurin.mod,
U4-PiecesOf8Bit.mod) and stream music/SFX from it — and link to those `.mod`
downloads from the website (so no audio is redistributed in the repo).

FINDINGS (from reading xu4-1.4.3 source, 2026-09-19):
- A `.mod` is a **CDI package** (custom binary archive). Magic bytes
  `DA 7A 70 00` + `78 75 34 02` ("xu4" v2). Defined by `src/support/cdi.{h,c}`
  in xu4; entries are indexed by FourCC app-id and a filename index.
- xu4-1.4.3 loads audio via `sound_faun.cpp`: `config_musicFile(id)` /
  `config_soundFile(id)` return a **`CDIEntry*`** (offset+length inside the
  mounted `.mod`), and the **Faun** audio library streams from that offset.
  Module mounting is in `src/module.c` (457 lines) + `src/support/cdi.c`.
- tu4 differs: audio is **SDL2_mixer** (`Mix_LoadMUS`/`Mix_LoadWAV` from a
  file PATH, `sound_sdl2.cpp`), and config is **XML** (`conf/music.xml`,
  `conf/sound.xml`) with loose filenames (`.it`/`.mid` music, `.ogg` SFX).
- HEAD START: **tu4 ALREADY has `src/support/cdi.c` (171 lines)** — the same
  CDI reader — so the archive format reader is present.
- CONFIRMED (2026-09-19): the standard `Ultima-IV.mod` shipped with EVERY xu4
  binary release (checked xu4-1.0beta5 AND xu4-1.4.3) packs ALL audio (music +
  SFX) as **Ogg Vorbis streams** (~1750 `OggS` signatures; no .it/.mid/.wav).
  SDL2_mixer plays Ogg natively, so the SDL_RWops bridge needs NO format
  conversion. So tu4 could consume the SAME `Ultima-IV.mod` xu4 distributes,
  and the website links to it (no audio redistributed in the tu4 repo).
- CDI FORMAT VERSION: magic is `DA 7A 70 00` + `78 75 34 vv` where vv is the
  version — **beta5 = v1 (`xu4\x01`), 1.4.3 = v2 (`xu4\x02`)**. The module
  reader must handle the target version(s); tu4's cdi.c version must match.

EFFORT ESTIMATE (~3-5 days), no Faun needed:
1. Port `module.c` mounting (open .mod, read CDI dir, index by name/app-id),
   adapting xu4's — reuse tu4's existing cdi.c. (~1-2d)
2. Load audio from a CDI entry via **SDL_RWops**: wrap the .mod file region as
   an SDL_RWops and use `Mix_LoadMUS_RW` / `Mix_LoadWAV_RW` (avoids swapping
   the SDL2_mixer backend for Faun). (~0.5-1d)
3. Resolve tu4's music.xml/sound.xml track names -> CDI entries in the mounted
   module. (~0.5-1d)
4. Reconcile format/filenames: .mod packages `.ogg` streams; tu4 music uses
   `.it`/`.mid` — map tu4's track list to the module's stream names. (~0.5d)
5. (Optional) module-selection UI like xu4's Game Module Browser.

Until then: the repo ships tu4's loose `mid/`+`sound/` (xu4-GPL assets; what
the SDL2_mixer path loads today).
