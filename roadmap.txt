tu4-1.0 Roadmap
===============

NEXT: Initiate New Game
------------------------
Prepare artwork in ASP (BSAVE text-mode) format for the
"Initiate New Game" sequence.

ASP files store 80x50 text-mode screens (8000 bytes payload + 7 byte
BSAVE header = 8007 bytes). Each cell is 2 bytes: character + attribute.
These go in the graphics/ directory alongside TITLE.ASP and MYSHAPES.ASP.

Asset files to prepare (illustrations for story sequence):

  TREE.ASP      - Forest/tree scene (storyInd 0-5, 11-14)
  PORTAL.ASP    - Moongate/portal scene (storyInd 6-10)
  OUTSIDE.ASP   - Outside scene (storyInd 15-16)
  INSIDE.ASP    - Inside building scene (storyInd 17-19)
  WAGON.ASP     - Gypsy wagon scene (storyInd 20)
  GYPSY.ASP     - Gypsy fortune teller scene (storyInd 21-22)
  ABACUS.ASP    - Abacus/cards scene (storyInd 23, also questions)

Name entry and sex selection use no illustration (just text prompts
over the existing intro screen, same as xu4).

Implementation notes:
- Text entry cursor (blinking block) needed for name input
- Single character input for sex (M/F) and question answers (A/B)
- Story text comes from TITLE.EXE string table (introText[0..23])
- Gypsy question text from TITLE.EXE string table (introGypsy[])
- drawCard() renders virtue cards on ABACUS illustration during questions


FUTURE
------
- Per-theme glyph font and colour palette. Goal: let a theme use its own
  character glyphs (e.g. EDSCII instead of IBM CP437) and its own colour
  palette (e.g. the Pepto C64 palette instead of EGA), instead of the
  compile-time defaults.

  Glyph font: DONE (2026-09-13). The SDL2 backend now loads the active
  theme's glyph bitmap from graphics/<textStyle>/cp437_8x8.bin (256 chars
  x 8 bytes = 2048 bytes, MSB-first per row: bit 0x80 = leftmost pixel).
  If the file is absent or the wrong size it falls back to the compiled-in
  cp437_font[] (cp437_8x8.h). Reloaded on Text Style change via
  screenInit_sys. loadThemeFont() + activeFont in screen_sdl2.cpp.
    * GOTCHA: the shipped theme cp437_8x8.bin files had been stored
      LSB-first (bit-mirrored); they were regenerated MSB-first to match
      the renderer (old copies kept as *.bin.lsb.bak). Any new theme font
      must be MSB-first or glyphs render horizontally mirrored.
    * TODO: mirror this in screen_sdl3.cpp (still uses compiled cp437_font
      directly). Only the SDL2 backend is wired so far.

  Colour palette: DONE for SDL2 (2026-09-13). The backend loads the active
  theme's 16-colour palette from graphics/<textStyle>/palette.bin, a flat
  48-byte file (16 colours x 3 bytes RGB, EGA index order matching the
  attribute nibbles). Falls back to the compiled egaPalette[16] if the file
  is absent or the wrong size. Reloaded on Text Style change.
  loadThemePalette() + activePalette in screen_sdl2.cpp.
    * Format reuses playscii palettes: graphics/converters/png2pal.py
      converts a playscii palette PNG (e.g. playscii/palettes/ega.png,
      c64_pepto.png) into palette.bin by scanning unique colours L->R/T->B
      (playscii's own ordering). The shipped U5-EGA/EGA palette.bin were
      generated from ega.png and are byte-equal to the compiled EGA palette
      (transparent fallback). converters/pepto.bin is ready for a future
      C64/Pepto theme.
    * TODO: mirror in screen_sdl3.cpp (still uses compiled egaPalette).

- Alternate screen and tile sizes: currently the display is fixed at
  80x50 characters with 4x4-character tiles. Plan to support larger
  screens (80x60 or 100x60) with 5x5-character tiles.

  Prep DONE (2026-09-13): "de-magic-number" pass — the scattered literal
  80/50 values were replaced with named constants in screen.h that
  separate the two roles they conflated:
    * SCREEN_COLS / SCREEN_ROWS       — destination text-screen size
    * ASP_SCREEN_COLS / ASP_SCREEN_ROWS / ASP_SCREEN_SIZE
                                      — full-screen ASP background stride/size
  (Behaviour-preserving: all constants still evaluate to 80/50/8000.)

  Remaining work (the actual behavioural change):
    * Make tile size theme-driven. TILE_WIDTH/TILE_HEIGHT are still a
      global #define in u4.h; the <image name="tiles" width= height=>
      attributes already exist in graphics-text.xml but are ignored.
      A 5x5-tile theme ships 5x5 tile art, so tile size logically belongs
      to the imageset, not a compile-time constant.
    * Recompute the derived layout areas that are tuned to 80x50:
      VIEWPORT_W/H (11 tiles -> at 5x5 that is 55 chars, no longer fits a
      44-char map area), TEXT_AREA_*, STATS_AREA_*, WIND_AREA_*, MOON_*,
      BORDER_*. Verify wrapping math (steering rule 3: viewport <= 2x map).
    * Re-author every full-screen ASP asset (TITLE/START/ANIMATE/TREE/...)
      to the new screen dimensions; ASP_SCREEN_SIZE changes accordingly.
    * Decide the axis of variation: is a "5x5 / 100x60" config a new THEME,
      a separate DISPLAY-MODE orthogonal to theme, or a matrix (theme x
      screen size)? Leaning: tile size -> per-theme; screen size + derived
      areas -> a selectable layout profile a theme can require.


  (2026-09-12) — separate _ew/_ns ASP files, side walls (dungeonhall)
  blue/green and facing walls (dung0ma) green/blue, so a wall's colour
  tracks its world orientation like xu4's EGA (fixup="dungns"). U5-EGA
  and PC9801 STILL share one file per orientation (both orientations look
  identical); give them separate _ns art if per-heading colour is wanted
  there too. tu4's fixupDungNS remains a no-op stub (no text-mode pixel
  swap); the split is done with pre-coloured files, not a load-time swap.

- SDL3 Migration (screen_sdl3.cpp, event_sdl3.cpp, sound_sdl3.cpp)
  Key SDL3 changes:
    Display: SDL_CreateWindow(title,w,h,flags), SDL_CreateRenderer(win,NULL),
             SDL_RenderTexture() replaces SDL_RenderCopy(),
             SDL_SetRenderLogicalPresentation() replaces SDL_RenderSetLogicalSize(),
             SDL_SetTextureScaleMode(tex, SDL_SCALEMODE_NEAREST)
    Events:  event.key.key (not event.key.keysym.sym),
             SDL_KMOD_ALT/CTRL/GUI/SHIFT,
             SDLK_A-Z (uppercase), SDL_EVENT_KEY_DOWN, SDL_EVENT_QUIT,
             Window events are top-level (SDL_EVENT_WINDOW_EXPOSED etc)
    Audio:   SDL3_mixer completely redesigned:
             MIX_Init/MIX_Quit, MIX_CreateMixerDevice,
             MIX_LoadAudio (replaces Mix_LoadWAV + Mix_LoadMUS),
             MIX_CreateTrack (replaces channels),
             MIX_SetTrackAudio + MIX_PlayTrack (replaces Mix_PlayChannel/Mix_PlayMusic),
             MIX_StopTrack, MIX_PauseTrack, MIX_SetTrackGain,
             MIX_SetMixerGain (replaces Mix_MasterVolume),
             MIX_DestroyMixer (replaces Mix_CloseAudio)
    Build:   -lSDL3 -lSDL3_mixer, include <SDL3/SDL.h>, <SDL3_mixer/SDL_mixer.h>
