tu4-1.0 Roadmap
===============

STATUS (2026-09-20)
-------------------
tu4 1.0 is feature-complete and playable in text mode. The full game loop is
integrated with the xu4 engine: title/intro sequence, "Initiate New Game"
character creation (gypsy questions + virtue cards), "Journey Onward" (load
saved game), main menu, Configure menu, world/town/city/castle rendering,
combat, the first-person 3D dungeon view, and the gem/peer views all work.
See README.md ("Status") and changes.txt for the detailed feature list.

The items that used to head this file ("NEXT: Initiate New Game" and a
bottom to-do list of Journey Onward / Configure menu / Dungeon view / Combat /
Town-city interaction) are all DONE and have been removed.

Asset delivery (2026-09-19/20, DONE): the package ships only the assets that
cannot be derived from Ultima IV; the rest (intro/story screens, codex/shrine
screens, dungeon object/monster tiles, TITLE, virtue cards) are regenerated on
first run by the bundled tu4-setup tool. See .kiro/steering/tu4-setup-pipeline.md.

Theme auto-discovery (2026-09-20, DONE): themes are discovered from
conf/themes/*.xml (gated on graphics/<NAME>/ being installed) and loaded
lazily, one active theme at a time. Drop conf/themes/NAME.xml +
graphics/NAME/*.ASP in place and it appears in Configure -> Text Style.


FUTURE
------
- Per-theme glyph font and colour palette. Goal: let a theme use its own
  character glyphs (e.g. EDSCII instead of IBM CP437) and its own colour
  palette (e.g. the Pepto C64 palette instead of EGA), instead of the
  compile-time defaults.

  Glyph font: DONE (2026-09-13, SDL2). The SDL2 backend loads the active
  theme's glyph bitmap from graphics/<textStyle>/cp437_8x8.bin (256 chars
  x 8 bytes = 2048 bytes, MSB-first per row: bit 0x80 = leftmost pixel).
  Absent/wrong-size -> falls back to the compiled cp437_font[] (cp437_8x8.h).
  Reloaded on Text Style change via screenInit_sys. loadThemeFont() +
  activeFont in screen_sdl2.cpp.
    * GOTCHA: the shipped theme cp437_8x8.bin files had been stored
      LSB-first (bit-mirrored); regenerated MSB-first to match the renderer
      (old copies kept as *.bin.lsb.bak). Any new theme font must be
      MSB-first or glyphs render horizontally mirrored.
    * TODO: mirror in screen_sdl3.cpp (still uses the compiled cp437_font
      directly). Only the SDL2 backend is wired so far.

  Colour palette: DONE (2026-09-13, SDL2). The backend loads the active
  theme's 16-colour palette from graphics/<textStyle>/palette.bin, a flat
  48-byte file (16 colours x 3 bytes RGB, EGA index order matching the
  attribute nibbles). Absent/wrong-size -> falls back to the compiled
  egaPalette[16]. Reloaded on Text Style change. loadThemePalette() +
  activePalette in screen_sdl2.cpp.
    * Format reuses playscii palettes: graphics/converters/png2pal.py
      converts a playscii palette PNG (e.g. playscii/palettes/ega.png,
      c64_pepto.png) into palette.bin by scanning unique colours L->R/T->B
      (playscii's own ordering). converters/pepto.bin is ready for a future
      C64/Pepto theme.
    * TODO: mirror in screen_sdl3.cpp (still uses the compiled egaPalette).

- Alternate screen and tile sizes: the display is currently fixed at 80x50
  characters with 4x4-character tiles. Plan to support larger screens
  (80x60 or 100x60) with 5x5-character tiles.

  Prep DONE (2026-09-13): "de-magic-number" pass — the scattered literal
  80/50 values were replaced with named constants in screen.h that separate
  the two roles they conflated:
    * SCREEN_COLS / SCREEN_ROWS       — destination text-screen size
    * ASP_SCREEN_COLS / ASP_SCREEN_ROWS / ASP_SCREEN_SIZE
                                      — full-screen ASP background stride/size
  (Behaviour-preserving: all constants still evaluate to 80/50/8000.)

  Remaining work (the actual behavioural change):
    * Make tile size theme-driven. TILE_WIDTH/TILE_HEIGHT are still a global
      #define in u4.h; the <image name="tiles" width= height=> attributes
      already exist in the theme XML but are ignored. A 5x5-tile theme ships
      5x5 tile art, so tile size logically belongs to the imageset, not a
      compile-time constant.
    * Recompute the derived layout areas tuned to 80x50: VIEWPORT_W/H
      (11 tiles -> at 5x5 that is 55 chars, no longer fits a 44-char map
      area), TEXT_AREA_*, STATS_AREA_*, WIND_AREA_*, MOON_*, BORDER_*. Verify
      wrapping math (steering rule 3: viewport <= 2x map).
    * Re-author every full-screen ASP asset (TITLE/START/ANIMATE/TREE/...)
      to the new screen dimensions; ASP_SCREEN_SIZE changes accordingly.
    * Decide the axis of variation: is a "5x5 / 100x60" config a new THEME,
      a separate DISPLAY-MODE orthogonal to theme, or a matrix (theme x
      screen size)? Leaning: tile size -> per-theme; screen size + derived
      areas -> a selectable layout profile a theme can require.

- Dungeon wall per-heading colour for non-EGA themes. (2026-09-12) The EGA
  theme uses separate _ew/_ns ASP files so a wall's colour tracks its world
  orientation like xu4's EGA (side walls dungeonhall blue/green, facing walls
  dung0ma green/blue; fixup="dungns"). U5-EGA and PC9801 still share one file
  per orientation (both orientations look identical); give them separate _ns
  art if per-heading colour is wanted there too. tu4's fixupDungNS is a no-op
  stub (no text-mode pixel swap); the split is done with pre-coloured files,
  not a load-time swap.

- SDL3 migration (screen_sdl3.cpp, event_sdl3.cpp, sound_sdl3.cpp). The SDL3
  backend files exist but are not the default build (SDL3_mixer is unavailable
  on the dev system, so UI=sdl2 is the shipping default). Key SDL3 changes:
    Display: SDL_CreateWindow(title,w,h,flags), SDL_CreateRenderer(win,NULL),
             SDL_RenderTexture() replaces SDL_RenderCopy(),
             SDL_SetRenderLogicalPresentation() replaces SDL_RenderSetLogicalSize(),
             SDL_SetTextureScaleMode(tex, SDL_SCALEMODE_NEAREST)
    Events:  event.key.key (not event.key.keysym.sym),
             SDL_KMOD_ALT/CTRL/GUI/SHIFT,
             SDLK_A-Z (uppercase), SDL_EVENT_KEY_DOWN, SDL_EVENT_QUIT,
             Window events are top-level (SDL_EVENT_WINDOW_EXPOSED etc)
    Audio:   SDL3_mixer completely redesigned:
             MIX_Init/MIX_Quit, MIX_CreateMixerDevice,
             MIX_LoadAudio (replaces Mix_LoadWAV + Mix_LoadMUS),
             MIX_CreateTrack (replaces channels),
             MIX_SetTrackAudio + MIX_PlayTrack (replaces Mix_PlayChannel/Mix_PlayMusic),
             MIX_StopTrack, MIX_PauseTrack, MIX_SetTrackGain,
             MIX_SetMixerGain (replaces Mix_MasterVolume),
             MIX_DestroyMixer (replaces Mix_CloseAudio)
    Build:   -lSDL3 -lSDL3_mixer, include <SDL3/SDL.h>, <SDL3_mixer/SDL_mixer.h>
  Also: mirror the per-theme font/palette loading (above) into the SDL3
  backend, which still uses the compiled defaults.

- Gameplay ideas inherited from xu4 (nice-to-have, not scheduled):
    * Ultima 5 style aiming in combat (angle shots).
    * More sound effects.
    * Allow the map view to display more of the world.
    * A formal modding system to extend the world or create new adventures.
